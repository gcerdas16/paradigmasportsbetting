INTRODUCCIÓN
¿Qué es SharpAPI?
SharpAPI es una plataforma de agregación de cuotas de apuestas deportivas en tiempo real que ofrece "actualizaciones de
cuotas  sub-segundo  de  las  principales  casas  de  apuestas  a  través  de  REST  o  streaming  SSE",  junto  con  detección
automatizada de valor esperado (EV) y alertas de arbitrage.
Características Principales
La plataforma proporciona:
•  Cuotas en tiempo real con latencia sub-segundo
•  Detección automatizada de valor esperado positivo utilizando referencias de casas de apuestas nítidas
•  Identificación de arbitrage entre casas con cálculos de apuestas óptimos
•  Streaming de Server-Sent Events para actualizaciones en vivo

GUÍA RÁPIDA DE INICIO
Base Setup
El API opera en "https://api.sharpapi.io/api/v1". Los usuarios deben registrarse en sharpapi.io para obtener una clave API que
comienza con "sklive".
Primera Solicitud Ejemplo
Una llamada básica para recuperar datos de cuotas:

curl -X GET "https://api.sharpapi.io/api/v1/odds?league=nba&sportsbook=draftkings&market=moneyline" \
  -H "X-API-Key: YOUR_API_KEY"
Estructura de Respuesta
•  data: Array de oportunidades de apuestas con casa de apuestas, deporte, equipos, tipo de mercado, formatos de
cuotas (Americano/Decimal) y probabilidad
•   meta:  Metadatos  mostrando  cantidad  de  resultados,  registros  totales  disponibles,  casas  participantes,  detalles  de
paginación y timestamp
Parámetros de Consulta para Filtrado
El API acepta parámetros para refinar resultados:
•  Filtrar por liga (ej: NBA)
•  Filtrar por casa de apuestas específica
•  Recuperar solo eventos en vivo usando "live=true"
•  Especificar tipos de mercado (moneyline, spread, total)
Características de Apuestas de Valor
Los  suscriptores  Pro  acceden  al  endpoint  de  oportunidades  para  apuestas  "+EV",  devolviendo  datos  incluyendo  IDs  de
oportunidad, nombres de eventos, cálculos de cuotas nítidas, porcentajes de EV y valores del criterio Kelly para gestión de
banca.
Actualizaciones en Tiempo Real
El  streaming  de  Server-Sent  Events  (SSE)  proporciona  notificaciones  instantáneas  para  cambios  de  cuotas,  nuevas
detecciones de EV y oportunidades de arbitrage a través de oyentes de eventos.

CONVENCIONES DE RESPUESTA
Estructura de Respuesta
Los códigos de estado HTTP determinan éxito/fallo, no los campos de respuesta. Los códigos de estado varían de "200"
(éxito con cuerpo) a "5xx" (errores del servidor), con "204" para eliminación y "302" para redirecciones.
Las respuestas exitosas utilizan dos formatos:
1.  No paginada: "{ "data": {...}, "updated_at": "..." }"
2.  Paginada: Añade un bloque de paginación con "limit", "offset", "count", "total", "hasmore" y "nextoffset"
Página 5
SharpAPI — Documentación Completa
Estándares de Campos
Todos los campos de servidor a cliente utilizan snakecase (ej: "eventid", "market_type"). Los timestamps siguen el formato
RFC 3339/ISO 8601 UTC como "2026-04-16T19:29:38.920698424Z".
Los campos de timestamp comunes incluyen "updatedat" (tiempo de emisión de respuesta) y "fetchedat" (tiempo de encuesta
ascendente).
Manejo de Errores
Las respuestas de error contienen: "code" (identificador estable), "message" (legible para humanos), link "docs" opcional y
"retryAfter" en límites de tasa.
Los códigos de error comunes incluyen "validationerror", "ratelimited", "tierrestricted" y "notfound".
Características de Rendimiento
•  Encabezados de límite de tasa rastrean "X-RateLimit-Limit", "X-RateLimit-Remaining" y timestamps de reinicio
•   Soporte  de  ETag  habilita  solicitudes  condicionales  a  través  de  "If-None-Match"  para  ahorrar  ancho  de  banda  en
cargas útiles grandes
•  IDs canónicos permiten unir entre endpoints (ej: formato de "eventid": "{league}{home}{away}{date}")
SharpAPI  publica  especificaciones  legibles  por  máquina:  OpenAPI  3.1  para  superficies  REST  y  AsyncAPI  3.0  para
WebSocket.

ENDPOINT DE DEPORTES
Solicitud: "GET /api/v1/sports"
Autenticación: Requerida (clave API en header "X-API-Key")
Disponibilidad: Todos los niveles, incluyendo nivel Gratuito
Descripción General
El endpoint de Deportes proporciona acceso a todos los deportes disponibles con sus ligas asociadas y conteos de eventos.
Información Clave
El endpoint devuelve una lista de deportes con estos puntos de datos:
•  Identificador del deporte y nombre para mostrar
•  Ligas asociadas dentro de cada deporte
•  Conteo de evento actual y conteo de evento en vivo
Deportes Disponibles
El API soporta 19 deportes incluyendo:
•  Basketball (NBA, NCAAB, WNBA)
•  Football (NFL, NCAAF)
•  Hockey (NHL)
•  Baseball (MLB)
•  Soccer (EPL, La Liga, Serie A, Bundesliga, MLS)
•  Tennis (ATP, WTA)
•  MMA (UFC)
Página 8
SharpAPI — Documentación Completa
•  Golf (PGA)
•  Deportes adicionales: Boxing, Cricket, Rugby, Lacrosse, Motorsports, Curling, Darts, Snooker, Table Tennis y Esports
Estructura de Respuesta
Cada objeto de deporte incluye:
•  "id": identificador en minúsculas para usar en filtros de API
•  "name": nombre del deporte legible para humanos
•  "leagues": array de IDs de liga
•  "event_count": total de eventos disponibles con cuotas
•  "live_count": eventos activos/en vivo actualmente
Uso en Filtros
Usar el ID del deporte para filtrar otros endpoints: "?sport=basketball" o "?sport=basketball,football" para múltiples deportes.
Nota: Los conteos de evento son dinámicos y reflejan calendarios actuales; los deportes fuera de temporada muestran cero
eventos.
ENDPOINT DE LIGAS
Ruta: "GET /api/v1/leagues"
Autenticación: Requiere autenticación por clave API en todos los niveles de suscripción
Descripción General
El endpoint de Ligas proporciona acceso a todas las ligas deportivas disponibles en el sistema SharpAPI. Es accesible a
través de "GET /api/v1/leagues" y requiere autenticación con clave API en todos los niveles de suscripción.
Parámetros Clave
El endpoint acepta un parámetro de consulta opcional:
•  "sport" (string): Filtra resultados por tipo de deporte (ej: basketball, football). Por defecto devuelve todas las ligas.
Estructura de Respuesta
Las respuestas incluyen un array "data" conteniendo objetos de liga y metadatos. Cada objeto de liga contiene:
•  "id": Identificador único para filtrado en otros endpoints
•  "name": Designación de liga legible para humanos
•  "sport": Clasificación del deporte padre
•  "event_count": Número de eventos actualmente disponibles con cuotas
•  "live_count": Eventos actualmente en juego

ENDPOINT DE MERCADOS
Acceso: "GET /api/v1/markets"
Autenticación: Requerida en todos los niveles de precios
Descripción General
El endpoint de Mercados ("GET /api/v1/markets") proporciona información sobre tipos de mercado de apuestas disponibles,
sus configuraciones y disponibilidad de deporte.
Parámetros de Consulta
•  sport (string, opcional): Filtrar resultados por identificador de deporte (ej: "basketball"). Por defecto devuelve todos los
mercados.
Estructura de Respuesta
La respuesta exitosa (HTTP 200) incluye:
•  array de data: Contiene objetos de mercado con información detallada
•  objeto meta: Incluye estadísticas de conteo y detalles de límite de tasa
Campos de Objeto de Mercado
Cada mercado contiene:
•  "id": Identificador único para filtrado en otros endpoints
•  "name": Título de mercado amigable para mostrar
•  "description": Breve explicación del tipo de mercado
•  "hasLine": Booleano indicando si existe un valor de línea numérica
•  "examples": Descripciones de selección de muestra
•  "event_count": Número actual de eventos que ofrecen este mercado
•  "selection_count": Total de selecciones únicas disponibles
•  "sports": Array de IDs de deporte soportados
Categorías Principales de Mercado
Mercados Principales (más ampliamente disponibles):
•  Moneyline (predicción de ganador)
•  Point Spread (apuestas de handicap con valores de línea)
•  Total Points (sobre/bajo de puntos combinados)
•  Team Total (predicciones de puntuación de equipo individual)
Mercados de Proposición:
•  Player Props (estadísticas de rendimiento individual con líneas)
•  Game Props (ocurrencias de juego específico)
Página 11
SharpAPI — Documentación Completa
Mercados Especializados:
•  Period Markets (1er tiempo, 1er cuarto, etc.)
•  Futures (resultados de temporada completa o campeonato)
Uso de Implementación
Los IDs de mercado funcionan como parámetros de filtro en todo el API. Por ejemplo, filtrado de solicitudes de cuotas por
"market=moneyline" o combinando múltiples mercados con "market=pointspread,totalpoints".
Variaciones de Cobertura de Deporte
La disponibilidad de mercado difiere por deporte. Las ligas profesionales (NBA, NFL, MLB, NHL) soportan tipos de mercado
comprensivos, mientras que deportes especiales como MMA y golf ofrecen mercados limitados. La designación "Limitada"
indica que ciertas casas de apuestas proporcionan mercados para eventos específicos solamente.
ENDPOINTS DE CUOTAS
ENDPOINT DE SNAPSHOT DE CUOTAS
Ruta: "GET /api/v1/odds"
Descripción General
El endpoint de Snapshot de Cuotas recupera cuotas de apuestas actuales de múltiples casas de apuestas. Está disponible
para todos los niveles de suscripción, aunque el acceso a libros específicos depende de tu plan.
Autenticación y Acceso
El endpoint requiere una clave API y está ubicado en "GET /api/v1/odds". Los usuarios de nivel Gratuito pueden acceder solo
a  DraftKings  y  FanDuel,  mientras  que  los  suscriptores  de  nivel  Sharp  obtienen  acceso  a  las  32  casas  de  apuestas
disponibles, incluyendo Pinnacle.
Parámetros de Consulta Clave
Opciones de Filtrado:
•  "sportsbook": IDs de libros separados por comas (limitado por nivel)
•  "sport"/"league": Filtrar por deporte o liga
•  "market": Filtrar tipos de mercado usando alias como "main", "spread", "total", "props" o tipos exactos
•  "event": IDs de evento específico
•  "live": Booleano para filtrar cuotas en vivo vs prematch
Paginación y Resultados:
•  "limit": Máximo 200 resultados por página (defecto 50)
•  "cursor": Recomendado para exploraciones de múltiples páginas (estable contra actualizaciones en vivo)
•  "offset": Paginación heredada (máx 500)
Ordenamiento y Selección:
•  "sort": Ordenar por cualquier campo (prefijo con "-" para descendente)
•  "fields": Devolver solo campos específicos
•  "minodds"/"maxodds": Filtrar por rango de cuotas americanas

•  "group_by=event": Agrupar resultados por evento en lugar de lista plana
Estructura de Respuesta
Las respuestas exitosas incluyen:
•  "data": Array de objetos de cuotas
•  "meta": Metadatos con conteos, libros disponibles e información de paginación
•  Encabezados de límite de tasa: "X-RateLimit-Limit", "X-RateLimit-Remaining", "X-RateLimit-Reset"
Campos de Objeto de Cuotas
Cada entrada de cuotas contiene: "id", "sportsbook", "eventid", "sport", "league", nombres de equipo, "markettype", "selection",
cuotas en formatos Americano/Decimal/Probabilidad, valor "line", timestamps e indicador de estado "is_live".
Mejor Práctica de Paginación
"Usar paginación basada en cursor para exploraciones de múltiples páginas" ya que los datos en vivo se actualizan cada ~15
segundos, causando posible desvío de fila con paginación basada en desplazamiento. Los cursores son opacos y válidos solo
para parámetros de filtro coincidentes.
Ejemplos de Código
cURL (básico):
curl -X GET "https://api.sharpapi.io/api/v1/odds?league=nba&sportsbook=draftkings&market=moneyline" \
  -H "X-API-Key: YOUR_API_KEY"
Python (paginación con cursor):
import requests
def fetch_all_odds():
    results = []
    params = {'league': 'nba', 'sportsbook': 'draftkings', 'market': 'moneyline', 'limit': 200}
    cursor = None
    
    while True:
        if cursor:
            params['cursor'] = cursor
        resp = requests.get(
            'https://api.sharpapi.io/api/v1/odds',
            params=params,
            headers={'X-API-Key': 'YOUR_API_KEY'}
        ).json()
        
        results.extend(resp['data'])
        pagination = resp['pagination']
        if not pagination['has_more']:
            break
        cursor = pagination['next_cursor']
    
    return results

El endpoint de Splits de Apuestas proporciona datos públicos de distribución de apuestas de casas de apuestas enfocadas en

Método de Cálculo de EV
SharpAPI usa Pinnacle como la referencia de "libro nítido". El proceso involucra:
1.  Extraer cuotas de libro nítido de Pinnacle

3.  Comparar contra libros suaves (DraftKings, FanDuel, BetMGM)
4.  Calcular EV: "(fairprobability × decimalodds - 1) × 100"
Como se afirma: "Libro nítido usado como referencia...Pinnacle"

Conceptos Principales
¿Qué es un Middle?
Cuando las casas de apuestas divergen en valores de línea, puedes colocar apuestas opuestas capturando ambos lados. Si
los  resultados  caen  entre  las  líneas,  ambas  apuestas  ganan  simultáneamente—a  diferencia  del  arbitrage,  esto  no  es
garantizado pero ofrece pagos sustanciales cuando tiene éxito.
Ejemplo de Estructura:
Si una casa ofrece Chiefs a -2.5 y otra ofrece Bills a +7.5, resultados donde Chiefs gana por 3-7 puntos dispara un "middle hit"
donde ambas apuestas tienen éxito.
Números Clave:
Los deportes exhiben patrones de puntuación (NFL: 3 y 7 puntos son márgenes comunes) que matemáticamente incrementan
la probabilidad del middle dentro de esos rangos.
Indicador de Ganancia Garantizada:
Cuando  "isguaranteedprofit"  devuelve  true,  el  middle  se  convierte  en  sin  riesgo—incluso  escenarios  perdedores  producen
retornos positivos porque las cuotas combinadas crean condiciones de arbitrage.

DESCRIPCIÓN GENERAL DE STREAMING
¿Por Qué Streaming?
SharpAPI proporciona actualizaciones de cuotas y oportunidades en tiempo real a través de dos protocolos de streaming:
SSE (Server-Sent Events) y WebSocket, ambos entregando "latencia sub-segundo" comparado con latencia del polling REST
de 30-60 segundos.
Problema que Resuelve el Streaming
El polling REST tradicional requiere frecuentes solicitudes de payload completo, creando demoras significativas. El streaming
resuelve  esto  enviando  solo  datos  cambiados  conforme  ocurren,  reduciendo  tanto  latencia  como  consumo  de  ancho  de
banda.
Dos Opciones de Protocolo
SSE (Server-Sent Events)
•  Comunicación HTTP, unidireccional
•  Reconexión automática vía "Last-Event-ID"
•  Ideal para aplicaciones consumidoras simples
•  Soporte nativo del navegador vía "EventSource"
WebSocket
•  Protocolo bidireccional "ws://" o "wss://"
•  Actualizaciones dinámicas de filtro sin reconectar
•  Reconexión manual con backoff requerida
•  Mejor para aplicaciones que necesitan comunicación bidireccional
Tipos de Evento Principales
La plataforma transmite múltiples categorías de evento:
•  "snapshot" / "snapshot:complete" — Dumps de datos iniciales
•  "odds:update" — Deltas compactos con solo campos cambiados
•  "ev:detected" / "ev:expired" — Oportunidades de apuestas de valor
•  "arb:detected" / "arb:expired" — Oportunidades de arbitrage
•  "middles:detected" / "middles:expired" — Oportunidades de middles
•  "heartbeat" — Señales de keep-alive cada 30 segundos

CONCEPTOS PRINCIPALES
FORMATOS DE CUOTAS
SharpAPI  entrega  cuotas  en  tres  representaciones  complementarias:  Americano,  Decimal  y  Probabilidad  Implícita,  todas
incluidas en un solo objeto de respuesta.
Cuotas Americanas
Este  formato  estándar  de  EE.UU.  indica  "cuánto  ganas  o  debes  arriesgar."  Los  números  negativos  muestran  el  riesgo
requerido para ganancia de $100; los números positivos muestran ganancia de una apuesta de $100.
Ejemplos:
•  -110: Arriesgar $110 para ganar $100 ($90.91 de ganancia)
•  +150: Arriesgar $100 para ganar $150
•  -200: Arriesgar $200 para ganar $100
•  +200: Arriesgar $100 para ganar $200
Cuotas Decimales
"Estándar en Europa/Australia," este formato muestra retorno total por unidad apostada, incluyendo la apuesta original.
Ejemplos:
•  1.909: $190.90 de retorno total ($90.90 de ganancia)
•  2.50: $250 de retorno total ($150 de ganancia)
•  1.50: $150 de retorno total ($50 de ganancia)
Probabilidad Implícita
Calculada como "1 / Cuotas Decimales," esto representa la probabilidad de resultado evaluada por el mercado. Un decimal de
2.00 equivale al 50%; 1.50 equivale al 66.7%; 3.00 equivale al 33.3%.
Advertencia importante: La documentación advierte que "la probabilidad implícita incluye el margen de la casa de apuestas
(vig)," siendo la probabilidad verdadera típicamente 2-5% más baja.
La Vig/Juice
Las casas de apuestas incrustan márgenes de ganancia en las cuotas. Un lanzamiento de moneda justo mostraría 2.00 en
ambos  lados  (100%  de  probabilidad  total),  pero  con  vig,  ambos  lados  muestran  1.91  (104.8%  de  probabilidad  total),
proporcionando la ventaja de la casa.

CÁLCULO DE VALOR ESPERADO
¿Qué es Valor Esperado?
El Valor Esperado cuantifica ganancia o pérdida promedio por apuesta durante el tiempo. La fórmula fundamental es:
"EV = (Probabilidad de Ganar × Ganancia) - (Probabilidad de Perder × Apuesta)"
EV Positivo (+EV) indica rentabilidad a largo plazo.
Ejemplo Práctico
Para un lanzamiento de moneda a cuotas +110:
•  Probabilidad de ganar: 50%
•  Pago de ganancia: $110
•  Cantidad de pérdida: $100
•  Cálculo: (0.50 × $110) - (0.50 × $100) = +$5 por cada $100 (5% EV)
Esto significa que esperas ganar $5 por cada $100 apostado consistentemente.
Metodología de SharpAPI
SharpAPI emplea Pinnacle (una casa de apuestas nítida) como el punto de referencia para probabilidad "justa". El proceso de
tres pasos:
1. Extraer Cuotas de Libro Nítido
Ejemplo: Pinnacle muestra Equipo A a -115, Equipo B a +105
2. Remover la Vigorisma
Convertir probabilidades implícitas eliminando la ventaja de la casa (vig) para determinar cuotas justas
3. Comparar Contra Libros Suaves
Calcular EV comparando probabilidad justa contra precios de casa de apuestas más suaves
Fórmula de EV
"EV% = (fairprobability × decimalodds - 1) × 100"

ARBITRAGE
¿Qué es Arbitrage?
El arbitrage ("arb") es una estrategia que explota diferencias de precios entre casas de apuestas para garantizar ganancias
sin importar el resultado del evento.
Concepto Fundamental
"Arbitrage explota diferencias de precio entre casas de apuestas para garantizar ganancia independientemente del resultado."
La esencia radica en que cuando la suma de probabilidades implícitas de todas las opciones es menor al 100%, existe una
oportunidad de ganancia sin riesgo.

Por Qué Existen Arbitrages
1.  Diferencias temporales: Los libros actualizan a velocidades distintas

4.  Errores: Ocasionalmente cometen equivocaciones

•  Cuentas limitadas o cerradas
•  Retiros demorados
•  Restricción a apuestas pequeñas

•  Redondear montos de apuestas ($50 en lugar de $47.32)
•  Mezclar con apuestas recreativas
•  Retiros graduales
•  Utilizar múltiples cuentas (donde sea legal)

COINCIDENCIA DE EVENTOS
Problema Principal y Solución
SharpAPI  aborda  un  desafío  fundamental:  cada  casa  de  apuestas  usa  diferentes  IDs  de  evento  internos  para  juegos
idénticos. Su solución es un ID de evento canónico que permanece consistente en todos los libros.
Página 47
SharpAPI — Documentación Completa
El formato sigue este patrón: "{league}{teamA}{teamB}_{YYYY-MM-DD}"
Ejemplo en plataformas:
•  DraftKings: "33483200"
•  FanDuel: "nba-bos-lal-20260208"
•  Pinnacle: "556677889"
•  Todos mapean a: "nbacelticslakers_20260208"
Sistema de ID Dual
Cada evento contiene dos tipos de identificador:
1.  ID Canónico ("id"): "Identificador entre libros sirviendo como tu clave de base de datos principal"
2.  IDs Externos ("external_ids"): Mapeo del identificador de evento nativo de cada casa de apuestas
Proceso de Generación de ID
El ID canónico combina cuatro elementos:
•  Código de liga (basketball se convierte en "nba")
•  Nombres de equipo normalizados (despojados de prefijos, sufijos, puntuación)
•  Equipos ordenados alfabéticamente (asegura consistencia independientemente de designación casa/visitante)
•  Fecha de inicio (formato YYYY-MM-DD)
La  normalización  de  equipo  maneja  variaciones  como  "Los  Angeles  Lakers,"  "LA  Lakers"  y  "LAL"  todas  reduciéndose  a
"lakers".
Aplicaciones Prácticas
Almacenamiento de base de datos: Usar el ID canónico como tu clave principal para eventos en todas las casas de apuestas
Comparación entre libros: Consultar cuotas para un evento canónico específico para comparar precios simultáneamente
Deep linking: Referenciar "external_ids" para dirigir usuarios a páginas de evento específicas de la casa de apuestas
Detección de oportunidad: El mismo sistema de coincidencia impulsa los motores de detección de EV, arbitrage y middles de
la plataforma internamente

Definiciones Clave
Cuotas  Prematch:  Establecidas  antes  de  que  los  juegos  comiencen,  contando  con  profundidad  de  mercado  integral,

•  Menús limitados de mercado en vivo (3-10 opciones)

•  Los mercados típicamente se reabren dentro de 30-90 segundos

+EV/Arbitrage en Vivo: Requiere nivel Sharp; usar Pinnacle como referencia con patrón de diseño "manejar gracefully precios

selección de libro.
ODDSCHANGEDAT DE PINNACLE
Concepto Principal
El campo "oddschangedat" de Pinnacle representa "el timestamp del escritorio de trading de Pinnacle — cuándo Pinnacle
reprecio por última vez esta línea específica." No es un timestamp del pipeline de SharpAPI.
Distinción Clave
Página 49
SharpAPI — Documentación Completa
La documentación clarifica dos campos separados:
•  "oddschangedat": Cuándo el escritorio de trading de Pinnacle movió la línea
•  "lastseenat": Cuándo el pipeline de SharpAPI observó por última vez la fila
Como se explica: "Una brecha grande entre los dos (últimavista "lastseenat" fresca, antiguo "oddschanged_at") significa que
Pinnacle está manteniendo la línea fija."
Por Qué las Líneas Aparecen Obsoletas
Pinnacle opera como un market-maker que reprecio solo cuando el flujo de trading actual necesita ajuste. Las tasas de datos
observadas para precios nuevos varían significativamente:
•  Soccer: ~94% tasa de datos nuevos
•  Tennis: ~66%
•  NHL: ~51%
•  MLB: ~18%
•  NBA: ~9%
Para mercados NBA y MLB especialmente, ventanas ociosas de 30+ minutos son comunes porque el escritorio de Pinnacle
simplemente no está moviendo precios.
Orientación Práctica
Monitorea "lastseenat" para frescura de pipeline. Si este timestamp es reciente pero "oddschangedat" es antiguo, Pinnacle
está  deliberadamente  manteniendo  líneas  fijas—esto  es  comportamiento  normal  del  market-maker,  no  un  problema  de
sistema.
